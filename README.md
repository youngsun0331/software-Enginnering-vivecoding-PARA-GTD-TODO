# GTD-PARA-Todo 시스템 구축 프로젝트

본 프로젝트는 GTD(Getting Things Done) 생산성 방법론의 워크플로우와 PARA 데이터 조직화 구조를 결합하고, AI 기반의 자동 분류 추천 기능을 더한 스마트 할 일 관리 웹 서비스 개발 프로젝트입니다.

---

# 1. 문제 정의 및 기획 배경

### 1.1 기존 생산성 시스템의 한계
* 시중에 존재하는 대부분의 Todo 애플리케이션은 단순 목록 나열 방식으로, 태스크의 성격에 따른 체계적인 분류와 아카이빙 기능이 부족함.
* GTD 방법론은 효과적이지만 사용자가 모든 할 일 항목을 매번 어떤 영역(Projects, Areas, Resources, Archives)에 배치할지 스스로 판단하고 분류해야 하므로 높은 인지적 피로감이 발생하며, 이는 시스템 사용을 중도 포기하게 만드는 주된 원인이 됨.

### 1.2 해결 방안
* 사용자가 카테고리 지정 없이 빠르게 할 일을 입력하면, AI가 맥락을 분석하여 적절한 PARA 카테고리를 자동으로 추천하는 시스템을 구축하여 사용자의 인지적 피로도를 낮추고 시스템 지속성을 확보함.

---

# 2. 타당성 분석 (Feasibility Study)

* **기술적 타당성:** 사용자가 입력한 단문 형태의 할 일 데이터를 네 가지 카테고리(PARA)로 분류하는 것은 현대 LLM API의 맥락 이해 능력으로 충분히 구현 가능함. 백엔드를 Node.js 기반의 RESTful API 형태로 독립 구축하므로 향후 iOS 네이티브 앱 확장 시 백엔드 자원을 100% 재사용할 수 있음.
* **경제적 타당성:** 초기 개발 단계에서는 무료 티어를 제공하는 클라우드 인프라(Supabase, Render, Vercel 등)와 AI API의 무료 크레딧을 활용하므로 운영 비용을 0원으로 통제 가능함.

## 4. 범위 관리 (Scope Management)

제한된 시간(13일) 내에 개발을 완료하기 위해 기능을 최소 기능 제품(MVP) 단계와 차기 개발 단계로 엄격히 분리합니다.

### 4.1 핵심 구현 범위 (MVP)
* **Inbox 수집 및 Brain Dump 기능:** 카테고리나 마감일 없이 한 줄 형태의 텍스트로 할 일을 빠르게 연속 등록하는 기능.
* **PARA 카테고리 지정 및 조회:** 등록된 할 일을 Project, Area, Resource, Archive 폴더로 분류하고 분류별로 조회하는 기능.
* **할 일 완료 처리 기능:** 할 일의 상태를 완료(Completed)로 변경하는 기능.
* **AI 연동 정리 및 추천:** 사용자가 수집함에 넣은 할 일의 맥락을 분석하여 적절한 PARA 카테고리를 추천하는 기능.

### 4.2 차기 구현 범위 (Backlog)
* 회원가입 및 정밀한 로그인 기능 (개발 초기에는 단일 사용자 고정 ID로 대체)
* 통계 및 리포트 화면
* 모바일(iOS) 전용 애플리케이션 UI 구현 및 App Store 배포

## 6. 위험 관리 및 우선순위 제어 (Risk Management)

> **리스크 요인:** 1인 개발 진행 중 우선순위를 놓치고 마이너한 기능(예: UI 디자인 수정 등)에 시간을 빼앗겨 마감일(6/7)을 준수하지 못할 가능성이 있음.

### 프로젝트 통제 규칙
1. **일일 작업 제한 (Timebox):** 하루에 배정된 1~2시간 동안은 오직 당일 설정된 WBS 작업만 수행하며, 핵심 기능 외의 작업은 '차기 구현 범위(Backlog)'로 이관하고 즉시 배제한다.
2. **진척도 시각화:** GitHub Projects(칸반 보드)를 개설하여 `Todo`, `In Progress`, `Done` 컬럼에 스프린트별 세부 이슈를 등록하고 현재 진행 상황을 엄격히 추적한다.
3. **가장 단순한 아키텍처 유지:** 완벽한 화면을 만들기보다, 기능이 정상 동작하는 HTML 구조를 먼저 완성한 뒤 여유 시간이 남을 때 UI 컴포넌트를 정제한다.
