📝 [요구사항 명세서] AI 기반 GTD-PARA-Todo 시스템
1. 프로젝트 개요
본 프로젝트는 데이비드 알렌의 GTD(Getting Things Done) 방법론과 티아고 포르테의 PARA(세컨드 브레인) 시스템을 결합하여, 사용자의 정보 분류 피로도를 최소화하는 AI 보조 개인 생산성 관리 웹 서비스를 구축하는 것을 목표로 합니다.

2. 핵심 데이터 모델링 (3대 엔티티)
단순한 '할 일' 목록을 넘어, 정보의 성격에 따라 데이터베이스 구조를 3가지로 분리하여 관리합니다.

노트 (Note): 당장 실행할 작업은 아니지만 가치 있는 지식이나 참고자료입니다.

반드시 PARA의 Areas(책임 영역) 또는 Resources(관심 자원) 중 하나의 카테고리 속성을 가집니다.

프로젝트 (Project): 단일 행동으로 끝날 수 없고, 2단계 이상의 작업이 필요한 복잡한 목표입니다.

하위에 여러 개의 '할 일(Task)'과 '노트(Note)'를 포함할 수 있습니다.

완료된 프로젝트는 Archives(보관소)로 이동됩니다.

할 일 (Task): 구체적이고 단일한 실행 단위입니다.

독립적으로 존재할 수도 있고, 특정 '노트'나 '프로젝트'에 종속(연결)될 수도 있습니다.

3. 기능 요구사항 (GTD 정보 처리 워크플로우)
모든 정보는 Inbox로 들어와 '실행 가능 여부(Actionable)'에 따라 7가지 상태로 자동/수동 분류됩니다.

단계 1: 정보의 수집
Inbox 등록: 사용자는 머릿속의 아이디어, 할 일, 메모 등을 텍스트 형태로 Inbox에 빠르게 수집합니다.

단계 2: 실행 불가능한 정보의 처리 (Actionable: No)
① 삭제 (Trash): 불필요한 정보는 즉시 삭제(Delete) 처리합니다.

② 보관 (Someday/Maybe): 당장 하지 않지만 언젠가 할 일은 Task로 저장하되, 상태를 SOMEDAY로 지정하여 메인 목록에서 숨깁니다.

③ 참고자료 (Reference): 실행할 일은 아니지만 보관해야 할 지식은 Note(노트)로 변환하여 Areas나 Resources에 저장합니다.

단계 3: 실행 가능한 정보의 처리 (Actionable: Yes)
④ 프로젝트 (Project): 복잡한 일인 경우, 새로운 Project 엔티티를 생성하고 하위에 세부 작업들을 기획합니다.

⑤ 즉시 완료 (2-Minute Rule): 2분 안에 끝낼 수 있는 일은 Task로 저장함과 동시에 상태를 DONE(완료)으로 처리합니다.

⑥ 위임 (Waiting): 타인에게 맡긴 일은 Task로 저장하고 상태를 WAITING(대기중)으로 설정하여 추적합니다.

⑦ 계획 (Next Action): 내가 직접 나중에 해야 할 일은 Task로 저장하고 상태를 TODO(진행 전)로 설정합니다. (필요시 마감일 지정)

4. AI 기반 자동화 요구사항 (핵심 차별점)
AI 자동 분류 추천: 사용자가 Inbox에 텍스트를 입력하면, 시스템 내부의 AI(LLM API)가 문장의 맥락을 분석합니다.

동작 방식: AI는 해당 정보가 위에서 정의한 7가지 처리 방식(삭제, 보관, 참고자료, 프로젝트, 즉시완료, 위임, 계획) 중 어디에 해당하는지 추천하고, 적절한 카테고리(Areas, Resources 등)를 화면에 팝업이나 버튼 형태로 제시합니다.

사용자 제어권: 사용자는 AI의 추천을 원클릭으로 수락하거나, 본인의 판단에 따라 수동으로 다른 분류를 선택할 수 있습니다.
